title: Dagon zkAPI

Dagon zkAPI lets a user fund a private note with USDC and authorize API
usage with Groth16 proofs generated in the browser. Each accepted authorization
consumes a nullifier; after usage settles, the server signs the next private
balance and anchor.

The ledger is the immutable Solana Anchor vault. Encrypt and other FHE systems
are outside the trusted money path.

These docs cover protocol v2 and circuit `zkapi-v2-concession-v1`: Groth16 over
BN254, Poseidon, note-bound Baby-JubJub commitments, and Schnorr signatures.

<Callout type="warn" title="Deployment prerequisites">
The implementation's fresh SBF build and complete funded local-validator
lifecycle pass. A funded production rollout still requires an explicit setup
trust decision plus review of the exact immutable program, vault and treasury
token accounts selected by the operator.
</Callout>

## Components

**The browser SDK** keeps note secrets, signed private state and recovery
journals locally. It verifies exact deployment pins, generates proofs in WASM,
and submits prepared Solana stages through Wallet Standard.

**`dagon-zkapi serverd`** verifies proof authorizations, rejects nullifier
reuse, issues short-lived provider credentials and settles measured usage in
USDC base units, one per metered micro-USD, with no price oracle.

**The Anchor vault, finalized indexer and challenger** maintain the active note
tree, verify on-chain Groth16 withdrawals, and challenge escape withdrawals
from a state that already authorized usage.

## Trust and privacy boundaries

Proofs hide note ID, deposit, balance, expiry, anchor and state signature.
Deposits, withdrawals, network metadata and timing remain public, and the API
provider sees prompts. The checked-in setup is single-party; artifact hashes
identify it but do not provide multiparty-ceremony security.

The current construction is not post-quantum. A future experimental FHE ledger
may implement `CreditLedger`, but it must not change request/vault semantics or
enter the production money path without a separate readiness review.
