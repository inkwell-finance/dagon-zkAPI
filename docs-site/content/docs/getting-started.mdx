The repository contains the Anchor USDC vault, Rust proof/runtime code,
browser SDK and operator services.
Use Node 24+, Rust, Solana CLI and Anchor 0.32.1.

## Build and verify

```bash
npm ci
npm test
npm run verify:assets
npm run verify:solana-vk
cargo test --locked --workspace
cargo test --locked --manifest-path protocol/rust/Cargo.toml --workspace
bash scripts/build-verifiable-program.sh --check
```

The unit suites do not prove deployment readiness. The release gates are the
verifiable program build above and the local-validator parity stack, which runs
the mainnet configuration (differing only in network identity) through the
funded deposit/request/settlement/mutual-close/escape/challenge/finalize
lifecycle.

## Browser integration

Install a reviewed immutable revision or its `npm pack` artifact. Configure the
SDK before wallet initialization:

```js
import { configureBrowserSdk } from '@dagon/zkapi-browser-sdk';
import client from '@dagon/zkapi-browser-sdk/client';

configureBrowserSdk({
  configUrl: '/dagon-zkapi/browser-config.json',
  workerUrl: '/dagon-zkapi/assets/zkapiWasmWorker.js',
});

await client.init();
const unsubscribe = client.subscribe(snapshot => renderBalance(snapshot));
```

For Solana, the host supplies a Wallet Standard account with
`solana:signTransaction`. The deployment configuration pins the finalized RPC,
genesis hash, immutable program, vault-state PDA, exact decimal-string chain ID,
USDC mint, treasury token account, signing keys and proof hashes. The SDK owns private note state,
proof generation, signed-transaction journals and recovery. Wallets need USDC
in their associated token account to deposit plus a little SOL for fees and rent.

Never log note secrets, proof witnesses, provider credentials or signed
transactions. Do not clear a durable stage journal from UI state.

## Operator services

```bash
cargo build --release --locked \
  -p zkapi-cli --bin dagon-zkapi \
  -p zkapi-indexerd --bin dagon-zkapi-indexerd \
  -p zkapi-serverd --bin dagon-zkapi-challenged \
  -p dagon-zkapi-deploy --bin dagon-zkapi-deploy

./target/release/dagon-zkapi --help
./target/release/dagon-zkapi-indexerd --help
./target/release/dagon-zkapi-challenged --help
```

Shared parameters are compiled in from `solana/profile/shared.json`. Each
ledger-facing command takes only a network identity file
(`--solana-identity`), an RPC URL and secrets. Use the examples in
`docker/aws/` and keep populated secret files mode `0600`.

## Proof setup

The selected setup belongs to `zkapi-v2-concession-v1`. Proving keys, verifying
keys, generated Solana constants and browser WASM must come from the same
release. The key header catches accidental mismatches; it does not establish
setup provenance.

Only when creating a new incompatible deployment:

```bash
./target/release/dagon-zkapi setup --output-dir protocol/setup/new-deployment
```

The vault's verifier and signing keys are immutable. Independently verify every
deployed identity before funding a wallet.
