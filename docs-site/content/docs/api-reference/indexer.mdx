---
title: Finalized indexer
description: Solana account reconstruction and privacy-safe depth-32 Merkle snapshots
---

The Solana-default indexer reads finalized vault/note/pending accounts and
reconstructs the complete local tree only when its root matches the finalized
vault account. The browser uses whole-tree snapshots for proofs without
revealing a selected note ID.

| Method and path | Result |
| --- | --- |
| `GET /health` | Process health |
| `GET /v1/tree/root` | Current root |
| `GET /v1/tree/next-note-id` | Next unused note slot |
| `GET /v1/tree/snapshot` | Tree snapshot for client synchronization |
| `GET /v1/tree/notes/{note_id}/path` | Occupied leaf and 32 siblings |
| `GET /v1/tree/notes/{note_id}/zero-path` | Empty-leaf path for insertion |

The root, leaf, and siblings use canonical BN254 field encodings. Duplicate,
wrong-owner, malformed or root-inconsistent Solana accounts fail closed.

Run it with the network identity file and a finalized RPC:
`dagon-zkapi-indexerd --solana-identity PATH --rpc-url URL [--listen ADDR] [--poll-interval-ms N]`
(or `dagon-zkapi indexer` with the same options).

An indexer cannot fake membership: clients and the vault recompute roots from
the supplied paths. Incorrect or stale paths can cause proving or transaction
failure. The deployment pins the vault and network independently of indexer
responses.

## Leaf binding and private path lookup

The tree uses Poseidon over the BN254 scalar field with 32 sibling levels.
Each occupied leaf binds the note ID, secret-derived registration, deposit,
and expiry. The note-bound request and withdrawal circuits use this exact
leaf in both membership verification and the signed balance commitment.
The indexer's `/v1` URLs are independent of the proof protocol's v2 version.

`GET /v1/tree/snapshot` returns
`{ root: Felt252, next_note_id: u32, leaves: Felt252[] }`. Clients can rebuild
the tree and derive paths locally without revealing a particular note ID in a
request URL. Tree endpoints return `503` while initial chain replay is
incomplete.

Use current-root sibling paths when submitting a deposit or a closed-leaf
retirement. Withdrawals, escapes, defeats and concession raises need no path:
a defeat or raise supplies only the original archived request proof with its
historical root; do not rewrite its public inputs to the indexer's latest root.
