`crates/zkapi-indexerd/src/http.rs` define the supported routes.

## Proof and field encoding

The active circuit revision is `zkapi-v2-concession-v1`, using the v2 JSON
shapes and public-input order. The proving/verifying keys and vault's Groth16
adapter must match that circuit and setup. Pin the circuit ID, artifact hashes,
Solana program/vault/genesis identity, USDC mint, treasury token account, and server signing keys for
the configured deployment.

BN254 field values use `0x`-prefixed hexadecimal strings. Solana-derived `u64`
chain IDs use canonical decimal strings so JavaScript never rounds them. The Rust type
`Felt252` carries BN254 scalar-field values; it does not select the
Stark field. Curve points use `{ x, y }` and Schnorr signatures use
`{ r_x, r_y, s }`.

An HTTP proof is `{ backend: "groth16_bn254", proof: base64 }`. Decoding
`proof` yields exactly 256 bytes: eight canonical, 32-byte big-endian BN254
base-field coordinates in the order `A.x, A.y, B.x.c0, B.x.c1, B.y.c0,
B.y.c1, C.x, C.y`. These same bytes are passed to the vault's proof adapter.
Public inputs are supplied separately and verified directly. The v2 proof
object has no `public_output_hash` or private witness envelope.
