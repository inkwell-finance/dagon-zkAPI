# Testing and Verification

From the repository root:

```bash
cargo test --release --manifest-path protocol/rust/Cargo.toml --workspace --locked
cargo test --release --workspace --locked
```

Protocol tests cover canonical fields and serialization, Merkle trees, native
wallet persistence, browser wallet state, compact proof encoding, commitment
binding, Solana bindings, and request/withdrawal/transition circuit
constraints. Root tests cover the active runtime HTTP paths, nullifier
persistence, challenge processing, and the Solana vault program, whose
real-proof regressions use `protocol/test-vectors/vault-challenge.json`
(regenerated by the `vault_challenge_fixture` example).

The SDK asset check is `node scripts/sync-sdk-assets.mjs --check` from the repository
root. Keep the committed WASM and key hashes synchronized with the setup
manifest. Key generation is a separate operation and is not required for
ordinary verification. The
[setup trust assumptions](../../setup/v2/README.md) apply.

The end-to-end gate is the local Solana validator stack in
[`scripts/localnet/`](../../../scripts/localnet): it loads the verifiable vault
build at the declared program id with the mainnet configuration from
`solana/profile/shared.json`, differing only in network identity, and checks
that parity before running real services and proofs against it.
